6.1 Project files and data access

The report is organised as a Quarto book. The chapter source files, _quarto.yml, references.bib, the data and figures folders, and renv.lock should be kept together in the Final Report project folder. The R chapters use relative paths so that they can be moved to another computer without retaining a personal Windows directory.

The group shares the project through its GitHub repository. The Final Report/data folder is the shared location for report data. For reproduction, retain the repository copy used for the report, or record its commit identifier, because the contents of the main branch can change.

The following files are used by the R chapters or record the evidence for the chromosome 12 target check.

File Use in the report
data/gse159717_rnaseq_deseq_5dpi_counts_raw.tsv Input count matrix for the Task 1 differential-expression analysis.
data/consensus_table.rds Generated by Task 1 and read by Task 2 to carry forward the consensus results.
data/Task3_variant_hits.csv Saved variant-carrier results used in Task 3.
data/Task3_site_snapshot.csv Guide, reference and alternate sequences and seven individual genotypes used for the Task 3 sequence comparisons.
data/Task3_chr12_on_target_summary.csv Fourteen guide–individual results, including both copy sequences, mismatch counts and PAMs.
data/Task3_chr12_on_target_variants.csv Four overlapping sites for 248forw, with the seven genotypes at each site; 28 rows in total.
data/Task3_chr12_environment.json Actual Python and pandas versions, operating system, input size, source, coordinates and coverage status.
data/Task3_chr12_input_header.txt Saved VCF header used to identify GRCh38 and check the sample names.
data/Task3_chr12_reference_exon.fasta Saved 267-base GRCh38 reference sequence used to verify both target-plus-PAM regions.
Task3_chr12_on_target.ipynb Executed Python notebook for the chromosome 12 raw VCF scan and local sequence reconstruction.

The original chromosome 1 and chromosome 2 VCF inputs are stored in the group’s Project/00_data/vcf_data folder. The filenames used in the original notebook are sampled_chr1.vcf and sampled_chr2.vcf. These files are the course-provided subset of 1000 Genomes variant data for the same seven individuals. They are separate from the small CSV exports used to render the revised Task 3 chapter.

The chromosome 12 check uses a separate, full-chromosome IGSR input: ALL.chr12.shapeit2_integrated_snvindels_v2a_27022019.GRCh38.phased.vcf. The compressed file is available from the IGSR 20190312_biallelic_SNV_and_INDEL release. The completed run used the unpacked VCF, 35,466,361,650 bytes, and selected the same seven sample IDs. Its header records GRCh38. This input has a different scope from the course-provided chromosome 1/2 subsets; the chromosome 12 results concern the two intended target regions only.

6.3 Reproduction workflow

To reproduce the report, obtain the project source files and data, retain their folder structure, and open Final Report.Rproj in RStudio. Use a fresh R session and restore the project dependencies recorded in renv.lock. Render the complete book in HTML format from the project folder. The book configuration lists the task chapters in analysis order and disables both execution caching and frozen results.

The stages have the following dependencies:

  1. Task 1 reads the RNA-seq count matrix, performs the DESeq2 and edgeR analyses, and writes the consensus results to data/consensus_table.rds.
  2. Task 2 reads those consensus results and documents the choice of OAS2, the first-exon sequence, CRISPOR settings and selected guides. Guide design is an external CRISPOR step. Repeating it requires the input sequence and settings reported in Task 2 and the corresponding saved tool exports.
  3. Task 3 reads the two original off-target CSV inputs and the two chromosome 12 result CSVs. It recalculates the sequence comparisons and regenerates the off-target genotype tables and chromosome 12 summary tables.

Rendering the book reproduces its enabled R calculations and tables from the saved inputs. The external CRISPOR analysis and both Python VCF scans are separate steps. Repeating the original chromosome 1/2 scan requires the original notebook code, sampled_chr1.vcf, sampled_chr2.vcf and the CRISPOR off-target export offtargetsguide.txt. The assembly, coordinate convention and strand orientation must agree between those inputs. The saved Task 3 CSVs allow the reported sequence and genotype interpretation to be reproduced, but do not by themselves repeat the original search for overlapping variants.

To repeat the chromosome 12 check:

  1. Open Task3_chr12_on_target.ipynb in VS Code or Jupyter and select the Python kernel. The recorded run used Python 3.13.0 and pandas 2.3.3.
  2. Obtain and unpack the chromosome 12 VCF above. In the first notebook cell, set VCF_PATH to the location of this file on your computer. The saved notebook contains the path used for the completed run; change that path for another computer. Keep the seven sample IDs and both target coordinates unchanged.
  3. Place a copy of data/Task3_chr12_reference_exon.fasta in the chr12_results folder printed by the first notebook cell to reuse the recorded reference. If it is absent, the reference-check cell downloads the exon sequence using the Ensembl URL recorded in the environment JSON. The target regions are chr12:112978698–112978720 and chr12:112978746–112978768, with 1-based inclusive coordinates on the forward strand.
  4. Restart the kernel and run all cells in order. The notebook checks the reference targets, confirms the VCF assembly and sample IDs, scans overlapping records, checks REF alleles, reconstructs both local copies and exports five result files. Continue to export only after the scan finishes without errors. The complete VCF was read for the recorded run.
  5. Copy the five exported Task3_chr12_* files from chr12_results into Final Report/data, keeping their filenames. Retain the executed notebook beside the QMD chapters as Task3_chr12_on_target.ipynb. Then render the book to regenerate the chromosome 12 tables from the new exports.

The recorded check returned zero overlapping records for 200forw and four for 248forw. All seven individuals have 0|0 at all four sites. The summary therefore contains 14 guide–individual rows, each with zero protospacer mismatches, TGG on both copies and two matching copies in the supplied calls. The variants export has 28 rows because it lists four sites for seven individuals. These counts are checks on the recorded output, not required results for a different VCF dataset.

The notebook reconstructs SNP alleles and flags alternate indels, complex calls, missing genotypes and uncertain phase for review. The saved environment records coverage_checked: false. Thus, a count of two matching copies describes the supplied calls; absence of a variant record is not proof of reliable sequence coverage. A fresh notebook run repeats the raw chromosome 12 scan, while rendering alone reads its exports.
